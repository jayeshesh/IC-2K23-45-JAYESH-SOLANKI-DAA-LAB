# Program Documentation Template

For every program, document:
1. Problem statement and approach
2. Algorithm
3. Pseudocode
4. Dry run
5. Best, average, and worst-case time and auxiliary-space complexity
6. Sample input/output
7. Genuine execution screenshots
8. Real-life application
9. Learning outcomes
10. Error handling and unit tests where possible

Do not claim a test passed unless it was actually run.
